# 可行性评估摘要

> 完整报告见工作区 `梦界物语_离线单机复活_可行性报告.docx`（21 页），此处为仓库内的精简版。

## 结论

技术上可行，但这是「重建服务端」级工程，不是「去联网」级改造。

客户端能独立运行（战斗、养成、UI、剧情全在本地），但它被设计成瘦客户端：
导灵/技能/关卡这些内容数据、玩家存档、抽卡结果、匹配与 PvP 全部由服务端持有。
服务端已随域名消失，复活 = 为它重新造一个服务端。

| 目标 | 说明 | 人日 |
|---|---|---|
| A 最小可玩 | 登录 → 编队 → 打一关 → 育成 → 抽卡 | 75–95 |
| B 完整复原 | 加任务/邮件/公会/排行/PvP | 190–280 |
| C 改包离线化 | 二进制改写客户端 | 80–150，不推荐 |
| D 重制 | 换引擎重写 | 600+ |

## 客户端画像

- Unity 5.5.2f1 + IL2CPP（metadata v22），armeabi-v7a + x86
- Assembly-CSharp：3,175 类型 / 23,544 方法
- 无场景文件（`BuildSettings.levels` 为空），启动靠 `RuntimeInitializeOnLoad`
- 2,867 个未压缩 SerializedFile（121.8 MB），无 UnityFS 包头

## 战斗是可离线的

`GP` 命名空间 292 个类：伤害公式（`CalcDmg_*` 10 个变体）、
技能效果（`SO_*` 45 个、`SC_*` 12 个）、ATB 时间轴、敌方 AI、波次与结算全部本地实现。
对网络的唯一依赖是开战握手与结算上报。

## 服务端契约

98 个 REST 接口，客户端用 `Server.Json` 命名空间下 48 个 DTO 反序列化。
登录接口 `user/login` 的返回体 `LoginJson` 内嵌 39 组主数据（导灵全表、技能表、关卡表……）。

详见 `04-protocol.md`。

## 致命缺口

1. **内容数据在服务端**——客户端不带导灵/关卡定义
2. **美术不全**——Live2D 模型与角色资源走 CDN，现已不可得（角色立绘可从公开维基回收 200 张）
3. **加密数据表**——1,098 张 TextAsset 用块加密，密钥在 native 层

## 三条路线

| 维度 | 私服（推荐） | 改包 | 重制 |
|---|---|---|---|
| 客户端改动 | 无 | 汇编级补丁 | 完全重写 |
| 可维护性 | 高 | 低 | 高 |
| 反作弊风险 | 无 | 高 | 无 |
| 推荐度 | ★★★★★ | ★★ | ★ |
